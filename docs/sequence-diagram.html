Local Architecture

How a submit becomes a confirmation

Two processes and a protobuf-encoded request-response cycle: the browser submits a config, gets an immediate received confirmation, then polls a status endpoint until settingsmanager has applied it 5 seconds later — all wired locally through nginx as a reverse proxy.

Browser nginx :8080 settingsmanager :9000

Phase 1Immediate response

nginx serves static/index.html. Clicking "Send" encodes the form as a modbus_messages.ServiceConfig protobuf message and posts it binary to POST /config/update; nginx passes it straight through to settingsmanager:9000, which registers the transaction and replies immediately with Confirmation{status: received}.

Phase 2Result via polling

The browser then polls GET /config/confirmations/{transactionId} once a second. settingsmanager flips the transaction to applied 5 seconds after submission; the next poll response carries that status and the browser stops polling.

sse-ngnix · nginx :8080 is the only public entry point, settingsmanager listens exclusively on 127.0.0.1.
