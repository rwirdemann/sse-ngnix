Local Architecture

How a submit becomes a confirmation

Three processes, one immediate request-response cycle, and a held-open SSE stream that gets written to 5 seconds later once the result is ready — all wired locally through nginx as a reverse proxy.

Browser nginx :8080 backend :9000 confirmations :9001

Phase 1Immediate response

nginx serves static/index.html. Clicking "Senden" sends the JSON from the textarea via POST /api/submit; nginx passes it straight through to backend:9000/submit, which replies with {"status":"received"} — before anything has happened in the background yet.

Phase 2Result over SSE

In parallel, the browser opens GET /confirmations and keeps the connection open. confirmations lets it hang until backend calls POST /confirmations itself after 5s — only then does confirmations write the result as text/event-stream into that very same open connection back to the browser.

sse-ngnix · nginx :8080 is the only public entry point, both Go services listen exclusively on 127.0.0.1.
